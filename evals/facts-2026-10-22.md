## Claude Code behaviour (code.claude.com: sub-agents, workflows, prompt-caching, model-config, costs, hooks, skills, context-window)

- A subagent's first request "doesn't read the parent's cache"; only a fork does.
  0.4.0's "dropping a tier forfeits cache reuse, because caches are model-scoped" was
  **wrong for subagents**; it holds for a main-loop `/model` switch.
- Subagent and workflow-agent cache TTL is 5 minutes by default, even on a subscription;
  main loop 1 hour only on a subscription within plan usage. Settings `promptCacheTtl`,
  `subagentPromptCacheTtl`; frontmatter `experimental.cacheTtl`.
- On Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 (API key or subscription) "changing
  effort keeps the cache".
- Workflow siblings share a prefix only with identical model, effort, agent type, tools,
  schema and working directory; matching siblings are held up to 5 s
  (`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS`).
- Subagents spawned from the main conversation start in the background by default; each
  result arrives "as a completion notification in a later turn".
- A Workflow script holds intermediate results, "so Claude's context holds only the final
  answer".
- `SendMessage` to a **completed** subagent resumes it with full history (not Explore or
  Plan). 0.4.0's "a returned call is not live: re-brief a fresh one" was **wrong**.
- Model resolution: call `model` → definition `model` (`inherit` = main) →
  `CLAUDE_CODE_SUBAGENT_MODEL` → main model. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` overrides
  definitions and calls. `CLAUDE_CODE_EFFORT_LEVEL` beats definition and call effort.
- `disallowedTools` "is applied first, then `tools` is resolved against the remaining
  pool". 0.4.0's "ignored whenever `tools` is set" (read from a 2.1.29x schema string) is
  **superseded**.
- Explore runs on the main conversation's model; Plan inherits; both skip CLAUDE.md and git
  status. 0.4.0's "cheapest cold start" was true of the prefix only.
- Worktree isolation branches from the default branch, not the parent's HEAD.
- Workflow concurrency: up to 16 by default, fewer with fewer CPUs;
  `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1-256. 0.4.0's `min(16, CPUs − 2)` is not
  documented.
- Effort defaults: `medium` on Opus 5.5, Sonnet 5.5, Haiku 5.5; `high` on Fable 5.1. "Opus
  5.5 at `medium` matches or exceeds Opus 5 at `high`." `max` "is prone to overthinking".
- Native-1M models auto-compact near 967K; `/autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`.
  After compaction an invoked skill body is re-injected capped at 5,000 tokens (25,000
  total) — why 0.5.0 puts the orchestrator-cost section in the first 5K tokens of SKILL.md.
- Hooks: `systemMessage` is "shown to the user"; `additionalContext` reaches Claude, and
  PreToolUse accepts it. 0.4.0's notes used `systemMessage` only.
- Skill listing budget is 1% of the context window in characters; descriptions of the
  least-used skills are dropped first when it overflows. Skill description limit 1,024
  characters (0.4.0's was 1,214; 0.5.0's is 915).
- Fast mode: Opus 5.5 GA, 2x price, up to 2.5x output tokens/s, no TTFT gain; caching
  multipliers apply on top. In Claude Code the first fast turn rebuilds the cache once;
  toggling after that keeps it.
- Task budgets: "not supported on Claude Code or Cowork surfaces". Batch: API only.
- In synced (claude.ai-uploaded) plugins on a local machine, skill `!` commands do not run
  and `${CLAUDE_SESSION_ID}` is not substituted — why `/intelligent-delegate:audit` tells
  Claude to run the script rather than injecting its output.
