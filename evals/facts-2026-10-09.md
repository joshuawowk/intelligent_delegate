### Haiku 5.5 long-prompt cliff — a real constraint, not a rounding error

`haiku_55` carries a second rate block:
`long_prompt:{above_prompt_tokens:1e5, input:0.5, output:2.5, cache_read:0.05}`

Above **100K prompt tokens** Haiku 5.5 bills **5x its base rate** ($0.50/$2.50).
Still below Sonnet, but the 20x advantage becomes 4x. The old "200K hard wall"
is gone; it is replaced by a soft price cliff at 100K.

## Corrections this forces on the repo

1. **"Haiku takes no effort setting"** — true for `claude-haiku-4-5`
   (capabilities are exactly `["context_management"]`), **false** for
   `claude-haiku-5-5`, which carries `"effort","max_effort","xhigh_effort"`
   and `default_effort:"medium"`. Since `haiku` now resolves to 5.5, the
   `mechanical` tier **can** carry an effort setting.

2. **"The Haiku 200K context trap"** — obsolete. Haiku 5.5 is `window:1e6`.
   Replaced by the 100K price cliff above.

3. **Output-ratio baseline (Haiku 1x / Sonnet 2x / Opus 4-5x / Fable 10x)** —
   wrong by an order of magnitude at the bottom. Haiku 5.5 output is $0.50
   against Sonnet's $10.

   | normalized to | Haiku 5.5 | Sonnet 5.5 | Opus 5.5 | Fable 5.1 |
   |---|--:|--:|--:|--:|
   | Haiku 5.5 = 1x | 1x | **20x** | 40x | 100x |
   | Sonnet 5.5 = 1x | **0.05x** | 1x | 2x | 5x |

   Haiku is **20x** cheaper than Sonnet on output, not 2x.

4. **Cache reads — our claim was inverted.** The tier-name suffix is a *dollar
   rate*, not a multiplier. `tier_4_20_cache_read_0_20` is $0.20/MTok against
   $4 input = **0.05x**, and `tier_10_50_cache_read_0_25` is $0.25 against $10 =
   **0.025x**. Both are *cheaper* than the 0.1x standard, not dearer. The
   sentence "a Fable advisor's cached input costs 2.5x the usual fraction" is
   backwards: it costs 0.25x the usual fraction.

5. **The effort x model grid prices models the plugin no longer uses.**
   Sonnet 5.5, Opus 5.5 and Haiku 5.5 publish **no `effort_cost_index`**. The
   load-bearing claim "sonnet @ xhigh = 2 x 2.41 = 4.8 effective units against
   opus @ high at 5.0 — a wash" is computed from **`claude-sonnet-5`**, and
   `sonnet` no longer resolves there. There is no published basis for that
   arithmetic on the current generation, and the API skill states Sonnet 5.5's
   effort levels are **recalibrated** from Sonnet 5. The claim must be retired,
   not re-derived.

6. **Default effort moved to `medium`** on all three 5.5 models (Sonnet 5 and
   Opus 5 both defaulted `high`). An agent definition that omits `effort` now
   gets `medium`, so the tiers that mean to be thorough must say so explicitly.

7. **The `Agent` tool now exposes `effort`.** Its schema in 2.1.295 accepts
   `effort: low|medium|high|xhigh|max`, gated by a usage norm (set it only when
   the user or an instruction asks). Our "How to set each knob" table marks this
   cell "❌ none", which was true when written. The plugin's rationale is now
   `tools`/`maxTurns`/`omitClaudeMd` plus effort-without-asking, not
   "effort is unreachable".

## Request-surface facts that bear on tiering (claude-api skill)

- **Sonnet 5.5**: `thinking:{type:"disabled"}` is a 400; use
  `{type:"between_tools"}` (effort `high` or below only). Effort default `high`
  at the API, `medium` in this harness's catalog — the harness sets its own.
  Migration guidance: start at **`medium`** for agentic coding and multistep
  tool use, **`low`** for chat, and it explicitly calls out
  **verification at low effort** as viable.
- Lower effort on a newer model often matches or beats the previous generation
  at high effort — which is the single most useful sentence for this plugin.
- Caches are model-scoped, so a multi-model cascade forfeits cache reuse; input
  dominates the bill for tool-using agents.
- `claude-haiku-5-5` carries a `haiku_5_5_early_stopping_guidance` capability;
  the 5.5 models carry `lean_prompt`, `per_turn_effort`, `silent_turn_reminder`.
